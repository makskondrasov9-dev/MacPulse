# Как утилита для iMac 2017 выросла в MacPulse: мониторинг, вентиляторы и очистка на Swift

Мой iMac 2017 всё ещё справляется с повседневной работой. Но хотелось лучше понимать, куда уходят ресурсы: что происходит с CPU, сколько памяти занято, чем нагружена Radeon и почему вентилятор стал слышнее. Так появился MacPulse — нативное приложение на Swift и SwiftUI, которое постепенно объединило мониторинг, управление поддерживаемыми вентиляторами, очистку и удаление программ.

Исходники открыты под MIT. Подписок, платных уровней, аккаунтов и телеметрии нет. В версии 0.8.1 минимальная целевая система снижена до macOS 13 Ventura; установщик содержит Intel x86_64 и Apple Silicon arm64.

## Сначала — показания, которым можно доверять

Для CPU и памяти используются Mach/Darwin API. Сеть считает изменения байтовых счётчиков интерфейсов между опросами, а не запускает внешнюю команду каждую секунду. Частота обновления настраивается от одной до трёх секунд. История для мини-графиков ограничена 12 точками.

На Intel температуры читаются через AppleSMC в IOKit. Среди проверяемых ключей — TC0D/TC0P для CPU и TG0D/TG0P для GPU. Но наличие ключа ещё не означает корректное показание: значение датчика дискового отсека TH0P на машине с переходником могло оказаться отрицательным. Такое поле лучше скрыть, чем уверенно показывать пользователю «−7 °C».

SMC и многие счётчики IORegistry — аппаратно-зависимые интерфейсы. Нельзя обещать одинаковый набор датчиков на всех Mac. Для Apple Silicon есть fallback на системный thermalState: он сообщает уровень тепловой нагрузки, а не выдуманную температуру в градусах.

## Почему Radeon показывала почти 100% VRAM

На 5K iMac выделенный драйвером пул памяти может быть почти заполнен даже без тяжёлой задачи. Выдавать его за активное использование — вводить пользователя в заблуждение. В разборе IOAccelerator мы отделили доступные показатели активной видеопамяти от выделенного пула, включая InUseVidMemoryBytes, и убрали фиксированное предположение о 4 ГБ.

Каждый обнаруженный GPU отображается отдельно. Для интегрированной графики важно объяснить, что память разделяется с системой. На Apple Silicon текущий набор общесистемных показателей ограничен: приложение не обещает численную загрузку GPU там, где реализованный источник её не отдаёт.

## Управление вентиляторами не должно быть скрытой побочной функцией

Просмотр датчиков не требует смены режима вентилятора. Для применения настроек нужен отдельный helper с явным подтверждением администратора. Он работает в текущей сессии, а не устанавливает постоянную службу. Есть автоматический режим, минимальные обороты и температурная кривая. При завершении сессии, сне или потере связи предусмотрено восстановление исходных минимальных оборотов.

Ручное управление сейчас предназначено для поддерживаемого Intel-оборудования; на Apple Silicon доступен режим чтения. Если вентиляторов нет, соответствующий раздел не показывается. Одновременно применять настройки несколькими утилитами управления вентиляторами не следует.

## Очистка: сначала границы доступа, затем удобство

CleanerActor выполняет файловые операции вне UI. Ручной режим показывает категории и размеры; пользователь выбирает, что удалить. Безопасный режим браузеров ограничен кэшем и не должен сбрасывать авторизации. Глубокая очистка требует подтверждения.

Проверки путей и снимков файлов нужны не только против случайной ошибки в строке. Между сканированием и удалением каталог может измениться. Символические ссылки внутри разрешённого кэша нужно обрабатывать как ссылки, не переходя к произвольной цели за пределами разрешённого дерева.

«Быстрая очистка» — отдельный компромисс: после сканирования она удаляет подходящие кэши, логи и доступное содержимое Корзины. Это постоянное удаление. Для контроля над категориями предназначен ручной режим. Пропуски занятого или недоступного кэша показываются спокойно, с подробностями по запросу.

Деинсталлятор ищет связанные файлы по Bundle ID и имени в пользовательской Library. Совпадение только по имени не доказывает принадлежность: такие результаты требуют проверки. Системные и запущенные приложения защищены; общие данные при дублирующих установках тоже учитываются. Универсальной гарантии нахождения каждого стороннего helper или общей папки здесь нет.

## Full Disk Access: нет волшебного публичного флага

В публичном ответе Apple DTS рекомендуется выполнять нужную файловую операцию и корректно обрабатывать отказ, а не опираться на внутреннее устройство базы TCC. У приложения нет надёжного публичного API для универсального ответа «Full Disk Access выдан». Поэтому индикатор в настройках — эвристика; окончательный результат определяется реальным доступом к файлам. Даже FDA не отменяет все механизмы защиты macOS. [Обсуждение с Apple DTS](https://developer.apple.com/forums/thread/114452).

Это рекомендация из публичного форума, а не индивидуальная проверка или одобрение MacPulse компанией Apple. Для обычного мониторинга Full Disk Access не нужен.

## Ventura и упаковка

Понижение deployment target — не просто замена числа в Package.swift. Новые варианты onChange и ContentUnavailableView получили проверки доступности и альтернативы для macOS 13. NavigationSplitView, MenuBarExtra, Charts и SMAppService остаются основой интерфейса и автозапуска.

Все 69 тестов проходят. Есть Universal-сборка и проверка минимальной версии обеих архитектур. При этом запуск на Sonoma и успешная компиляция под Ventura не заменяют испытание на настоящей Ventura: такие отчёты от пользователей особенно полезны. Поддержка архитектуры также не означает физическую проверку всех моделей M1–M4.

Установщик пока подписан ad-hoc, без Developer ID и нотариального заверения Apple. В README есть объяснение первого запуска, контрольная сумма и инструкция для собственного Homebrew tap. Это не публикация в официальном homebrew/cask.
